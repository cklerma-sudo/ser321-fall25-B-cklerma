# Peer-to-Peer Chat System

### Link to Video: https://youtu.be/UXJpPCUKTaM

## How to Run
You can use the gradle command "runPeer --args "[Name] [Port Number]" in order to begin the peer to peer network. After that to add more peers in the network you must use the same command and append a port number that is already in the network. For example, "gradle runPeer --args "Bob 8001 8000" would create a user named bob that is at port 8001 and will attempt to connect to the whole network via the bootstrap peer at port 8000. Everything will be run on localhost.

## Algorithm Explanation
The automatic peer discovery works like introducing a new friend into an existing friend group. Each peer keeps a set of known peer ports (knownPeerPorts) and listens for incoming connections. To join the network, a new peer must know the port of at least one existing “bootstrap” peer. It opens a TCP connection to that bootstrap and sends a line-based control message HELLO [myPort]. The bootstrap adds this new port to its knownPeerPorts and replies with a PEERS port1,port2,... message that lists every peer it currently knows about. The new peer parses this PEERS message and then calls connectToPeer on each port in the list, establishing direct TCP connections to all existing peers. When those peers accept the incoming connection, they add the new socket to their listeningSockets and receive a HELLO [newPort] message on that socket, allowing them to learn the new peer’s port and include it in their own knownPeerPorts.
The protocol itself is a simple line-oriented text protocol over TCP. Control messages use plain text commands: HELLO [port] to announce a peer’s listening port and PEERS [comma-separated ports] to share the current membership list. Any line that does not start with HELLO or PEERS is treated as a chat message encoded as JSON, containing a username and message field. These JSON messages are broadcast to all connected sockets in listeningSockets, so each peer effectively “speaks” publicly to everyone it’s connected to while choosing which ports it wants to connect and listen to.

## Design Decisions
I prevent duplicate connections by each peer having a list of other peers that goes through various checks to ensure that only one can be added at a time. This list is also kept thread-safe and ensures that only one thread can access it at a time. This list makes it easy to check if there is ever a duplicate and the thread safety ensures that only one thread can access it. If two peers try to join simultaneously they one would go through the process of being connected and added to each peers' list and when that one completes the other will be allowed to do the same because of the thread-safe methods that are used. As of right now there is no way to build a network outside of "localhost" but it would not be too hard to implement. As a result, there is a limit to the amount of peers that can be in the network, but that is limited by the hardware and how many threads you can spin up, or the amount of ports.
